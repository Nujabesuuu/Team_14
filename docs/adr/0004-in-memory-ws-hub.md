# ADR-0004: WebSocket-хаб у пам'яті одного процесу

**Статус:** прийнято для MVP · 2026-09-19

## Контекст

Реальний час потрібен для чату, сповіщення про метч, зміни reveal та статусу івенту. Продукт запускається локально одним процесом `uvicorn`.

## Рішення

`app/ws/hub.py`: `ConnectionHub` тримає `dict[user_id, set[WebSocket]]` у пам'яті. Сервіси викликають `hub.send_to_user(s)` після коміту транзакції. Помилка відправки в мертвий сокет ковтається і сокет видаляється.

## Аргументи

- Нуль інфраструктури: працює в тестах (`TestClient`), локально і в `docker compose` з одним інстансом API.
- Клієнт має HTTP-фолбек для відправки повідомлень і авто-реконект з експоненційною затримкою, тому втрата сокета не втрачає дані.

## Наслідки

- Кілька реплік API не бачитимуть з'єднань одна одної. Перший крок масштабування — Redis pub/sub: сервіс публікує подію в канал `user:{id}`, кожна репліка доставляє її своїм сокетам.
- `--reload` у dev рве сокети при зміні коду; клієнт перепідключається сам.
