# ADR-0009: REST `/api/v1` + WebSocket і єдиний формат помилок

**Статус:** прийнято · 2026-10-27

## Контекст

Клієнт і сервер пишуть різні люди з різними ШІ-асистентами. Без жорсткого контракту клієнт починає розбирати тексти помилок, а сервер — віддавати різні формати у різних місцях. Продукт має багато заборон із бізнес-причиною (вік, блокування, згода), і клієнт повинен показати людині зрозумілу реакцію, не знаючи внутрішніх деталей.

## Варіанти

| Критерій | **REST + WebSocket** | GraphQL | gRPC / tRPC |
|---|---|---|---|
| Документація без зусиль | OpenAPI генерується FastAPI (`/docs`) | Схема є, але потрібен окремий сервер | gRPC — protobuf; tRPC — лише TypeScript-бекенд |
| Реальний час | WebSocket поруч | Subscriptions, складніше | gRPC streams, у браузері — ні |
| Кешування і відлагодження | Звичайні HTTP-інструменти, curl | Один ендпоінт, складніше | Потрібні спецінструменти |
| Поріг входу для команди | Низький | Середній | Високий |

**Формат помилок:** порівнювали RFC 7807 `application/problem+json`, стандартний формат FastAPI (`{"detail": ...}`, де `detail` то рядок, то масив) і власний конверт `{code, detail}`. RFC 7807 надлишковий для одного клієнта; формат FastAPI неоднорідний. Обрали власний конверт, сумісний з наявним клієнтом.

## Рішення

1. Усі ендпоінти під `/api/v1`; ресурси у множині (`/events`, `/matches`); дії над ресурсом — `POST /events/{id}/join`.
2. Кожна помилка, зокрема валідація, неіснуючий маршрут і непередбачений збій, повертається одним форматом:

   ```json
   { "code": "EVENT_FULL", "detail": "This event is full" }
   ```

   - `code` — стабільний UPPER_SNAKE_CASE ідентифікатор. Клієнт розгалужується лише за ним.
   - `detail` — текст для людини англійською. Клієнт може показати його, але не розбирає.
   - `fields` — лише для `VALIDATION_ERROR`: список `{field, message}`.
3. HTTP-статуси мають фіксоване значення (див. [contracts/errors.md](../contracts/errors.md)): 401 — немає або протух токен, 403 — є токен, але немає права, 404 — ресурсу немає, 409 — конфлікт стану, 422 — порушено бізнес-правило або валідацію, 429 — ліміт, 402 — потрібен Teamate+.
4. Помилки WebSocket — повідомлення `{ "type": "error", "code": "...", "detail": "..." }` з тими самими кодами.
5. Сервіси кидають лише `ApiError(status, code, detail)` з `app/core/errors.py`. Голий `HTTPException` у коді заборонено.

## Наслідки

- Клієнт має одну функцію розбору помилок (`api/client.ts`) і таблицю повідомлень за кодом.
- Новий код помилки — це зміна контракту: спершу [contracts/errors.md](../contracts/errors.md), потім сервер і клієнт.
- Версія в шляху дозволяє колись додати `/api/v2`, не ламаючи встановлені APK.

## Коли переглянути

Якщо з'являться сторонні клієнти API — перейти на RFC 7807 з тим самим `code` як розширенням.
