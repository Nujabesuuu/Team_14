# ADR-0003: Поступове розкриття фото — індивідуальне, за згодою власника

**Статус:** прийнято · 2026-09-18

## Контекст

Початкова ідея: фото приховані для всіх, преміум-підписка відкриває їх. Аналіз показав дві проблеми: (1) це суперечить цінності «спершу гра, а не зовнішність», і люди обійдуть оплату обміном Instagram; (2) людина, яка не платила, показується платнику без згоди — питання безпеки, особливо для жінок у геймінгу.

## Рішення

- Таблиця `photo_reveals` містить **по рядку на кожного учасника метчу**. `stage` описує, наскільки чітко *моє* фото бачить інша сторона.
- Стадії: 0 — незнайомець (blur 24 px + grayscale), 1 — метч (12 px), 2 — зіграли разом після метчу (4 px), 3 — чітко.
- Стадія 3 настає **тільки** коли `consent_next=true` в обох. Одностороння згода не змінює нічого, окрім підказки другій стороні.
- Преміум може надіслати `early_request`; без `early-accept` від другої сторони він нічого не відкриває.
- Стадії ніколи не регресують (`stage_after_shared_event = max(current, 2)`).

## Аргументи

- Кожен контролює лише своє зображення — базова вимога згоди.
- Преміум лишається пов'язаним з фото (ідея тімліда збережена), але як *прискорення прохання*, а не як обхід згоди.
- Момент «обоє натиснули — фото проявилось» стає емоційним піком продукту, а не транзакцією.

## Наслідки

- Для демо без завантажених фото показується маска; стадія все одно видима (`REVEAL 3/3`).
- Симетрична стадія 3 для обох спрощує UI, але означає, що не можна «відкрити своє, не побачивши чуже». Це свідомо: reveal — взаємний акт.
