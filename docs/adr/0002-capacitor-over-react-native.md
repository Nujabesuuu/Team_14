# ADR-0002: Capacitor замість React Native для Android

**Статус:** прийнято · 2026-09-18

## Контекст

Продукт мобільний. Вимога тімліда: «React, крутий візуал і простота; надалі перекомпілювати в Android».

## Рішення

Один React-вебзастосунок (mobile-first, 390×844), який пакується в Android через Capacitor. Ніякого окремого нативного клієнта.

## Аргументи

- **Один код — три цілі:** браузер (демо на курсі, дві вкладки = два акаунти), PWA, Android APK.
- **Повний контроль над візуалом:** `clip-path`, CSS-анімації, Google Fonts, framer-motion працюють як у браузері. У React Native довелося б переписувати всю дизайн-систему під інші примітиви.
- **Простота відлагодження:** DevTools, hot reload, Vitest + jsdom.
- **WebSocket і fetch** — стандартні API без бриджів.

## Наслідки

- Продуктивність WebView нижча за нативну; для чату і карток це непомітно, для важкої графіки — стало б проблемою.
- Нативні можливості (push-сповіщення, камера) потребують плагінів Capacitor — поза MVP.
- Папка `android/` генерується локально (`npx cap add android`) і не комітиться.

## Відкинуті альтернативи

- **React Native / Expo** — не веб, інший набір компонентів і стилів, складніша інтеграція дизайн-системи.
- **PWA + Trusted Web Activity** — теж варіант, але Capacitor дає зрозумілий шлях до Play Store і плагінів.
- **Next.js** — SSR не потрібен для мобільного застосунку і заважає статичній збірці під Capacitor.
