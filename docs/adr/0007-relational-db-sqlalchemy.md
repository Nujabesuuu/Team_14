# ADR-0007: Реляційна БД (SQLite локально, PostgreSQL у Docker) через SQLAlchemy 2 async

**Статус:** прийнято · 2026-10-27

## Контекст

Дані Teamate мають сильні зв'язки й інваріанти, які мають триматися навіть за помилки в коді:

- одна пара людей — не більше одного метчу (`uq_match_pair`);
- одна відповідь «Зіграємо ще?» на пару в межах івенту (`uq_feedback_pair`);
- не можна двічі приєднатися до івенту (складений первинний ключ `event_participants`);
- каскадне видалення: акаунт → профіль, участі, повідомлення.

Водночас кожен у команді має запускати проєкт локально без встановлення сервера БД, а демо повинно мати ті самі дані, що й тести.

## Варіанти

| Критерій | **SQLite + PostgreSQL через SQLAlchemy** | Лише PostgreSQL | MongoDB | Firebase / Supabase |
|---|---|---|---|---|
| Унікальність пар і зовнішні ключі | Так, на рівні БД | Так | Лише унікальні індекси, без FK | Firebase — ні; Supabase — так |
| Запуск без установки | SQLite — один файл | Потрібен Docker або локальний сервер | Потрібен сервер | Потрібен інтернет і акаунт |
| Бюджет | 0 | 0 | 0 | Безкоштовний тариф з лімітами |
| Тести | In-memory SQLite, 72 тести за ~30 с | Окремий контейнер у CI | Окремий контейнер | Емулятор |
| Async з FastAPI | `aiosqlite` / `asyncpg` | `asyncpg` | `motor` | SDK |
| Знайомість команді | SQL з курсу | SQL | Ні | Ні |

**ORM:** SQLAlchemy 2 (typed `Mapped[...]`) порівнювали з SQLModel і «сирим» SQL. SQLModel молодший і гірше підтримує async-зв'язки; сирий SQL дає більше коду і ручних маперів.

**Міграції:** Alembic порівнювали з `Base.metadata.create_all` на старті. Поки немає реальних користувацьких даних, `create_all` дешевший: зміна схеми = видалити `teamate.db`, і seed відновить демо-дані.

## Рішення

- Одна схема в `apps/api/app/models/`, два драйвери: `sqlite+aiosqlite` за замовчуванням і `postgresql+asyncpg` у `docker compose`. Вибір — змінна `DATABASE_URL`.
- Типи, сумісні з обома БД: `Uuid`, `DateTime(timezone=True)`, `JSON` для коротких списків (`modes`, `schedule`), `Enum` для перелічень.
- Схема застосовується автоматично під час старту API (`create_all`). Підключення до БД перевіряється ендпоінтом `GET /api/v1/health/db`.
- Усі зв'язки, що читаються в HTTP-обробнику, мають `lazy="selectin"`, бо ліниве завантаження в async-сесії падає з `MissingGreenlet`.

## Наслідки

- Нуль налаштувань для локального запуску; PostgreSQL перевіряється через Docker.
- Різниця діалектів (наприклад, порівняння часу з часовим поясом у SQLite) може сховати баг, який з'явиться лише в PostgreSQL. CI зараз ганяє лише SQLite — це прийнятий ризик.
- Без міграцій зміну схеми не можна накотити на наявну БД зі збереженням даних.

## Коли переглянути

Перед першим запуском із реальними користувачами (тестова група з інтерв'ю): підключити Alembic і зробити початкову міграцію з поточних моделей. Якщо з'явиться другий інстанс API — лише PostgreSQL.
