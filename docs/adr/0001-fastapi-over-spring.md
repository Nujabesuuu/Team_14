# ADR-0001: FastAPI замість Spring Boot для бекенду

**Статус:** прийнято · 2026-09-18

## Контекст

У команди базові навички Java (курс це припускає). Тімлід попросив «Python там, де доречно», React для клієнта і можливість зібрати Android. Бекенд MVP — це CRUD + кілька доменних правил + WebSocket.

## Рішення

FastAPI + SQLAlchemy 2 (async) + Pydantic 2.

## Аргументи

- **Швидкість ітерацій.** Схеми Pydantic дають OpenAPI-документацію і валідацію без окремих DTO/маперів; сервіс на 25 ендпоінтів написано і покрито тестами за один день.
- **Тестованість домену.** Чисті Python-модулі в `app/domain` тестуються без контейнера і без БД (35 тестів за 0,4 с).
- **WebSocket з коробки** без додаткових залежностей.
- **Розрахунок сумісності і майбутня аналітика** природно живуть у Python-екосистемі.

## Наслідки

- Команді доведеться освоїти async SQLAlchemy (пастка: ліниві relationship → `MissingGreenlet`; правило — `lazy="selectin"` для всього, що читається в HTTP-обробнику).
- Java-навички команди використовуються менше, ніж могли б. Компроміс усвідомлений: пріоритет — працюючий продукт до кінця семестру.

## Відкинуті альтернативи

- **Spring Boot** — більше шаблонного коду, повільніший цикл «зміна → тест», WebSocket складніший у налаштуванні.
- **Django REST Framework** — синхронний за замовчуванням, ORM менш зручний для async WebSocket.
