# Журнал використання ШІ

Вимога курсу: фіксувати, як саме генеративний ШІ використовувався, що з його пропозицій прийнято, що відкинуто і чому. Формат: дата · етап · що просили · результат · рішення команди.

## 2026-09-15 · КТ1 · ідея та README

- **Запит:** оцінити ідею «дейтинг для геймерів через спільну гру» як маркетолог, 1–100.
- **Результат:** 58/100. Головні ризики: монетизація «плати за фото» суперечить цінності продукту й обходиться обміном Instagram; змішування LFG і дейтингу; cold start; 18+.
- **Рішення:** прийняли критику. Переробили модель: фото розкривається поетапно за взаємною згодою, преміум продає видимість/зручність, режими Duo/Friends/Dating розділено, Dating 18+. Ідею «голосове інтро» відкинули (тімлід: не для MVP). Переоцінка: 74/100.

## 2026-09-18 · КТ3–4 · специфікація

- **Запит:** стек і архітектура під вимоги курсу (UI + backend + БД, Android надалі, React + Python).
- **Результат:** spec `docs/superpowers/specs/2026-09-18-teamate-mvp-design.md`: React + Capacitor / FastAPI / PostgreSQL-SQLite, доменні правила окремим шаром, WebSocket для реального часу.
- **Рішення:** прийнято. Альтернативи React Native і Next.js відкинуто свідомо (ADR-0002). Замість Java Spring (база команди) обрано FastAPI — ADR-0001.

## 2026-09-19 · КТ5 · реалізація

**Згенеровано ШІ і прийнято після перевірки тестами:**
- доменні модулі `events.py`, `matching.py`, `reveal.py`, `compatibility.py` та 35 юніт-тестів до них;
- REST-роутери, сервіси, схеми; 31 API-тест (httpx + in-memory SQLite);
- дизайн-система Phantom UI, 8 SVG-масок, усі екрани;
- seed-скрипт з 12 профілями.

**Дефекти в згенерованому коді, знайдені під час ручної перевірки в браузері (не тестами):**

| Дефект | Як знайшли | Виправлення |
|---|---|---|
| Картка в Discover і екран фідбеку залишались невидимими (`opacity: 0`) | Скриншот + `getComputedStyle` | `initial` на прямих дітях `AnimatePresence` не стартує під StrictMode у framer-motion 13. Замінено на CSS-анімацію `.deal-in`. Зафіксовано в design-system.md |
| `<button>` всередині `<button>` (Chip у картці івенту) | Попередження React у консолі | `Chip` рендерить `<span>`, якщо не має `onClick` |
| API стартував з порожньою БД | 401 при логіні з seed-акаунтом | Дефолтний шлях до SQLite залежав від `cwd`; тепер обчислюється від кореня `apps/api` |
| Форма логіну розтягувала поля на весь екран, тінь кнопки була не тієї висоти | Скриншот | `alignContent: start` для grid-форм; тінь `PhantomButton` загорнута в content-sized wrapper |
| `Conversation.match` лениво завантажувався в async-сесії → `MissingGreenlet` | Падіння API-тесту | `lazy="selectin"` |
| WebSocket-тест зависав | Таймаут pytest | Змішування event loop httpx і `TestClient` над одним in-memory SQLite; тест переписано повністю на `TestClient` |

**Відкинуті пропозиції ШІ:**
- Alembic-міграції на старті — зайве для MVP, `create_all` достатньо (зафіксовано як обмеження в architecture.md).
- Redis pub/sub для WS одразу — передчасно; описано як наступний крок (ADR-0004).
- Typing-індикатори в чаті — YAGNI.

**Що перевіряла команда самостійно:** повний демо-сценарій у двох вкладках (див. demo.md), усі 66 бекенд- і 25 фронтенд-тестів, `ruff`, `tsc`, `oxlint`, production-збірка Vite.

## Правила роботи з ШІ в команді

1. Кожен PR з ШІ-кодом має тести на доменні правила, які він реалізує.
2. Ніякого коду, який автор не може пояснити на рев'ю.
3. Чутливі дані (реальні email, паролі, токени) у промпти не потрапляють — лише seed-дані.
4. Візуальні зміни перевіряються в браузері, не тільки тестами: типові ШІ-дефекти (анімації, вкладеність DOM) тести не ловлять.
