# Технічні контракти

> **КТ4, крок 3.** Домовленості між клієнтом, сервером і базою даних. Код у `apps/` пишеться під ці документи, а не навпаки.

| Документ | Що всередині |
|---|---|
| [data-schema.md](data-schema.md) | Таблиці, типи полів, PK/FK/UQ, enum-и, ER-діаграма, відповідність історіям |
| [api.md](api.md) | Ендпоінти REST під кожну історію MVP: тіла запитів, відповіді, коди успіху й помилок; протокол WebSocket; трасування історія → ендпоінт |
| [errors.md](errors.md) | Єдиний формат помилок `{code, detail}`, значення HTTP-статусів, каталог усіх кодів |
| [openapi.json](openapi.json) | Машинна специфікація вже реалізованих ендпоінтів (експорт з FastAPI) |

**Як читати позначки:** ✅ реалізовано і покрито тестами · 🆕 контракт зафіксовано, реалізація на КТ5 разом з історією · ✏️ ендпоінт є, але контракт змінюється, щоб відповідати вимогам КТ3.

**Як оновлювати openapi.json** (API має бути запущений):

```bash
curl -s http://localhost:8000/openapi.json > docs/contracts/openapi.json
```

Промпт, яким проєктували контракти: [prompts/4.3_technical_contracts.md](../../prompts/4.3_technical_contracts.md).
