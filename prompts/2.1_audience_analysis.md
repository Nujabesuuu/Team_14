# 2.1 Аналіз цільової аудиторії

**Мета:** отримати від ШІ кілька чітко розмежованих профілів користувачів Teamate і обрати з них, кого MVP обслуговує першим.

**Як запускали:** новий чат з LLM. Промпт 2.2 надсилали в **той самий** чат одразу після відповіді на цей, бо він спирається на згенеровані персони.

## Фінальна версія промпту

```text
Дій як Senior UX Researcher, який 5+ років досліджує аудиторію дейтинг- і геймінг-продуктів.

Я розробляю мобільний застосунок «Teamate». Нижче повний опис проєкту.

<опис проєкту>
Що це. Мобільний застосунок (Android через Capacitor, React-клієнт; бекенд FastAPI + PostgreSQL) для знайомств між геймерами. Логіка обернена до Tinder: не «фото → оцінка → знайомство», а «спільна гра → симпатія → фото за взаємною згодою».

Проблема (гіпотеза). У дейтинг-застосунках рішення приймають за секунди по фото; сором'язливим людям важко почати розмову «ні про що»; перша зустріч з незнайомцем некомфортна. Геймерам бракує компанії для гри, а пошук тіммейтів розпорошений по Discord-серверах і внутрішньоігрових чатах без профілів і без способу продовжити знайомство.

Основний цикл. Івент → спільна гра → «Зіграємо ще?» → метч → чат → поступове розкриття фото → ігрове побачення.

Що вже працює в MVP:
- Реєстрація; режим «Побачення» доступний з 18 років (вік вказується самостійно, без перевірки документів).
- Профіль «Ігрова ДНК»: ігри, роль, стиль (для розваги / на результат), голос чи текст, розклад, толерантність до токсичності → відсоток сумісності між двома людьми.
- Аватар-маска героя замість фото; власне фото можна завантажити, але іншим воно показується розмитим.
- Режими Дуо / Друзі / Побачення; романтичні свайпи бачать лише ті, хто увімкнув «Побачення».
- Ігрові івенти: створити, приєднатись; хост натискає «Старт» і «Завершити». Інтеграції з API ігор немає: факт гри підтверджує лише хост.
- Після завершення івенту кожен учасник таємно відповідає про кожного іншого: «ще раз як тіммейт» / «хочу ближче» / «ні». Взаємне «ближче» = метч.
- Свайпи профілів (20 лайків на день безкоштовно); взаємний лайк теж = метч.
- Чат у реальному часі (текст), блокування користувача.
- Розкриття фото у 4 стадії: 0 — сильний блюр для всіх; 1 — після метчу; 2 — після ще однієї спільної гри; 3 — чітке фото лише коли обоє натиснули «Показати».
- Game Date: івент на двох зі «спокійними» іграми (Among Us, Overcooked, GeoGuessr).
- Teamate+ (поки без оплати): хто тебе лайкнув, необмежені свайпи, скасування свайпу, запит на раннє розкриття фото (друга сторона все одно має погодитись).

Заплановано пізніше: селфі-верифікація, прив'язка Steam/Discord/Riot ID, рейтинг «хороший тіммейт», скарги й модерація, Teamate Nights (регулярні офіційні івенти у фіксований час), подвійні побачення 2 на 2, реальні платежі.

Обмеження. Команда з 4 студентів, один семестр, без бюджету на маркетинг. Стартовий ринок — Україна; перша спільнота, з якої плануємо старт, — студенти нашого університету, які грають.

Конкуренти, про яких знаємо. Tinder/Bumble, Kippo (дейтинг для геймерів), GameTree (пошук тіммейтів), LFG-канали в Discord.
</опис проєкту>

Завдання: визнач 3–4 кандидатні профілі (персони) цільової аудиторії, а потім обери з них 1 основний і 1–2 вторинні профілі для MVP.

Для кожного кандидатного профілю опиши:
1. Коротке ім'я-архетип і одне речення «хто це».
2. Демографію (вік, зайнятість, місто з огляду на стартовий ринок) та ігровий бекграунд: у що грає (змагальні шутери/MOBA, кооперативні, сюжетні консольні, мобільні), скільки годин на тиждень, соло чи з компанією, голос чи текст.
3. Психотип: рівень екстраверсії, ставлення до знайомств онлайн, що відчуває, коли треба писати першим.
4. Головну мотивацію відкрити Teamate і тригер: у який конкретний момент тижня чи дня виникає потреба.
5. Чим користується зараз (Tinder/Bumble, Discord-сервери, внутрішньоігрові чати, Kippo, GameTree, друзі) і чому це не працює саме для цієї людини.
6. Що змусить цю людину видалити Teamate після першого тижня.
7. 3 питання, які варто поставити реальним людям цього профілю на інтерв'ю, щоб перевірити наші припущення.

Після цього:
- Обери 1 основний профіль (кого обслуговуємо першим у MVP) і 1–2 вторинні. Поясни вибір через силу болю, частоту потреби і те, наскільки поточний MVP вже її закриває.
- Опиши 1 анти-персону: кого ми свідомо НЕ обслуговуємо і чому.

Правила:
- Не вигадуй статистику й дослідження. Якщо наводиш цифру, познач її як «[гіпотеза]»: ми перевіримо її самі.
- Уникай загальних фраз на кшталт «усі, хто любить ігри». Кожен профіль має відрізнятися мотивацією, а не лише віком.
- Відповідай українською у структурованому markdown (заголовок на кожен профіль, списки, без довгих абзаців), щоб команда могла взяти текст за основу для User Stories.
```

## Що змінили порівняно з першою версією і чому

| Було | Стало | Навіщо |
|---|---|---|
| `[ВСТАВТЕ СЮДИ ПОВНИЙ ОПИС ПРОЄКТУ]` | Повний опис з фактами MVP, обмеженнями, ринком і конкурентами | Без контексту модель описує «геймерів загалом», а не наших користувачів |
| «Визнач 3–4 профілі» | 3–4 кандидати → вибір 1 основного, 1–2 вторинних і анти-персони | Чотири рівноправні персони = продукт «для всіх». Нам потрібен фокус для MVP |
| — | Заборона вигадувати статистику, цифри позначати `[гіпотеза]` | LLM впевнено генерують неіснуючі відсотки й дослідження (галюцинації) |
| — | Тригер використання і причина видалити застосунок | Мотивація без моменту використання не допомагає писати User Stories |
| — | 3 питання для інтерв'ю на кожен профіль | Персони від ШІ — гіпотези. Питання дають спосіб їх перевірити на живих людях |
