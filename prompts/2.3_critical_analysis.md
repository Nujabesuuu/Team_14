# 2.3 Критичний аналіз ідеї (асистент-критик)

**Мета:** змусити ШІ шукати слабкі місця, нереалістичні припущення й приховані ризики Teamate, а не хвалити ідею.

**Як запускали:** в **окремому новому** чаті, який не бачив наших персон і VPC. Критик має бути незалежним від висновків, які ми вже зробили, тому опис проєкту вставлено в промпт повністю.

**Сира відповідь ШІ:** [docs/research/2.3_critical_output.md](../docs/research/2.3_critical_output.md). Рішення команди щодо кожного ризику в [README.md](../README.md#7-критичний-аналіз).

## Фінальна версія промпту

```text
Дій як максимально скептичний Tech Lead, Security Engineer і Product Advisor, який запускав соціальні застосунки й бачив, як вони помирають. Твоє завдання — розкритикувати концепт «Teamate» і знайти найслабші місця, нереалістичні припущення та приховані ризики. Не підбадьорюй і не хвали: команді потрібні проблеми, а не компліменти.

<опис проєкту>
Що це. Мобільний застосунок (Android через Capacitor, React-клієнт; бекенд FastAPI + PostgreSQL) для знайомств між геймерами. Логіка обернена до Tinder: не «фото → оцінка → знайомство», а «спільна гра → симпатія → фото за взаємною згодою».

Проблема (гіпотеза). У дейтинг-застосунках рішення приймають за секунди по фото; сором'язливим людям важко почати розмову «ні про що»; перша зустріч з незнайомцем некомфортна. Геймерам бракує компанії для гри, а пошук тіммейтів розпорошений по Discord-серверах і внутрішньоігрових чатах без профілів і без способу продовжити знайомство.

Основний цикл. Івент → спільна гра → «Зіграємо ще?» → метч → чат → поступове розкриття фото → ігрове побачення.

Що вже працює в MVP:
- Реєстрація; режим «Побачення» доступний з 18 років (вік вказується самостійно, без перевірки документів).
- Профіль «Ігрова ДНК»: ігри, роль, стиль (для розваги / на результат), голос чи текст, розклад, толерантність до токсичності → відсоток сумісності між двома людьми.
- Аватар-маска героя замість фото; власне фото можна завантажити, але іншим воно показується розмитим.
- Режими Дуо / Друзі / Побачення; романтичні свайпи бачать лише ті, хто увімкнув «Побачення».
- Ігрові івенти: створити, приєднатись; хост натискає «Старт» і «Завершити». Інтеграції з API ігор немає: факт гри підтверджує лише хост.
- Після завершення івенту кожен учасник таємно відповідає про кожного іншого: «ще раз як тіммейт» / «хочу ближче» / «ні». Взаємне «ближче» = метч.
- Свайпи профілів (20 лайків на день безкоштовно); взаємний лайк теж = метч.
- Чат у реальному часі (текст), блокування користувача.
- Розкриття фото у 4 стадії: 0 — сильний блюр для всіх; 1 — після метчу; 2 — після ще однієї спільної гри; 3 — чітке фото лише коли обоє натиснули «Показати».
- Game Date: івент на двох зі «спокійними» іграми (Among Us, Overcooked, GeoGuessr).
- Teamate+ (поки без оплати): хто тебе лайкнув, необмежені свайпи, скасування свайпу, запит на раннє розкриття фото (друга сторона все одно має погодитись).

Заплановано пізніше: селфі-верифікація, прив'язка Steam/Discord/Riot ID, рейтинг «хороший тіммейт», скарги й модерація, Teamate Nights (регулярні офіційні івенти у фіксований час), подвійні побачення 2 на 2, реальні платежі.

Обмеження. Команда з 4 студентів, один семестр, без бюджету на маркетинг. Стартовий ринок — Україна; перша спільнота, з якої плануємо старт, — студенти нашого університету, які грають.

Конкуренти, про яких знаємо. Tinder/Bumble, Kippo (дейтинг для геймерів), GameTree (пошук тіммейтів), LFG-канали в Discord.
</опис проєкту>

Проаналізуй проєкт за критеріями:
1. Технічні ризики та архітектура: як підтвердити, що гра справді відбулась (зараз це підтверджує лише хост)? Як уникнути фейкових підтверджень і накрутки метчів? Що дасть і скільки коштуватиме інтеграція з API платформ (Riot, Steam, Discord)?
2. Cold start («курка та яйце»): як застосунок житиме в перший тиждень, коли івентів мало, а користувачі не бачать фото один одного? Чи не здасться він мертвим?
3. UX-тертя у воронці «Івент → Гра → Зіграємо ще? → Метч → Чат → Розкриття фото»: де люди відвалюватимуться найчастіше і чому?
4. Безпека, приватність і модерація: харасмент під час гри, обхід вікових обмежень (вік зараз вказується самостійно), неможливість модерувати голосові чати в сторонніх іграх, захист фото, яке має лишатися прихованим.
5. Продукт і бізнес: чи не вб'є поєднання «пошуку тіммейта» і «дейтингу» обидва сценарії? Чи заплатять за Teamate+? Чому людина не залишиться в безкоштовному Discord?

Формат відповіді:
- Список із 5–7 найкритичніших «смертельних загроз», впорядкований за ймовірністю × наслідками.
- Для кожної загрози: суть (2–3 речення), чому вона специфічна саме для Teamate, і чи загрожує вона навчальному MVP до кінця семестру, чи лише реальному запуску.
- Для кожної загрози одне жорстке питання до конкретної ролі в команді (Team Lead / Full-stack, Backend і System Design, DevOps, BA і QA), на яке треба відповісти до початку наступної ітерації розробки.
- Для кожної загрози 1–2 можливі шляхи зниження ризику, щоб команді було з чого обирати.

Правила: жодних загальних ризиків, які підходять будь-якому застосунку («може бути мало користувачів»); кожна загроза має спиратися на конкретну механіку Teamate. Не вигадуй статистику. Відповідай українською, markdown.
```
